# 次日接替安排裁决

跨夜加班结束后，次日岗位名单按以下规则形成可执行安排（模块 `m8_handover`）。

## 逐项对应

每个接替项目由同一份批次数据推导，字段一一对应：

- **超时班次**：员工前一班次（实际下班晚于计划下班即为超时，记录超时分钟与计薪切段工作分钟）。
- **休息截止**：实际下班 + 最低休息时长（参数 `min_rest_hours`，默认 12 小时，须在 0–24 之间）。
- **待接替岗位**：该员工次日班次，其计划开工早于休息截止即触发接替，缺口分钟 = 休息截止 − 岗位开工。
- **确认人员**：候选人不与岗位时段冲突、且自身最近一次下班后满足最低休息；无候选人记为空岗。确认人必须来自候选人集合。

## 失效与重新核对

安排 ID 为 `sha256('handover/'+run_id)`，而 `run_id` 已含输入字节、参数与规则版本。补卡规则更新产生新批次，新安排生成成功时旧安排整体置为 `已失效`（状态翻转，不删除），其确认记录保留在原安排上备查；新安排须逐项重新确认，并在发布前随计薪切段重新核对。

## 幂等

- 同一变更重跑：`plan_id` 相同，`INSERT OR IGNORE` 不重复生成，已有确认原样保留。
- 确认以 `(plan_id, item_id)` 为主键：同人重复确认是无操作；换人须提交当前确认版本，版本不符返回 409。

## 失败保留与记录不丢

生成先算后写、单事务落库；任一步失败不写库，当前可执行名单保持旧版，页面与接口自动回退展示旧版并给出告警。原始打卡批次在 `runs` 表只增不改；确认记录独立成表，失效仅翻转状态。

## 页面与导出同源

页面、`/api/m8_handover`、CSV 导出均读取当前安排（最新批次的安排，失败时回退 `handover_current` 指针），不重算、不各自为政。

## 发布对平

发布前用存储批次的原始打卡重算提案并逐项比对：休息截止、岗位、超时班次、员工必须一致；确认人须在重算候选与人员名册内；不得存在 `待确认` 项（空岗允许）。任一不符返回 409/422，不予发布。重复发布同一安排返回当前状态，不产生副作用。
